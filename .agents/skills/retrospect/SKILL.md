# retrospect — 判断の振り返り

trading-tools の `review` ツールの出力だけを材料に、過去の判断と助言の傾向を **事実として** 列挙し、閾値と助言の書き方の改善案を出す。**設定（`config/detect.json`）や助言スキルは変えない**。変えるかどうかは人が判断する。設計は Design Doc 0014。

## 手順

1. `pnpm review history --since <30 日前の日付>` を実行し、`rows`（判断の一覧）と `summary`（stance × 判断の件数と、その後の変化率の中央値）を読む
2. 気になる銘柄があれば `pnpm review timeline <code> --days 90` で出来事の並びを読む
3. 次を報告する
   - **傾向**: `summary` をそのまま表にする。件数が 3 未満の組は「件数が少ない」と明記する
   - **助言と結果のずれ**: 守りの `reduce` を「対応した」後に株価が上がった、ウォッチの `candidate` を「見送り」した後に上がった、など。銘柄・日付・変化率を添える
   - **閾値の調整案**: 同じ kind のアクションが繰り返し「見送り」になっているなら、その kind の閾値を緩める案。根拠（件数・中央値）を添える。案は `config/detect.json` の該当キーと値で書く
   - **助言の書き方の改善案**: `advise` スキルに追記すべき点があれば
4. 変化率は株価だけの話で、判断の良し悪しはそれだけでは決まらないことを最後に添える

## やってはいけないこと

- `config/detect.json` や `.agents/skills/*` を書き換える
- 「正解率」のような点数を付ける
- `review` の出力に無い事実（相場の状況など）を根拠にする
- SQLite を直接読み書きする
