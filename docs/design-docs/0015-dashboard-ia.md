## 1. 背景と目的

M1〜M5 で画面を足すたびに上部ナビにリンクを並べてきた結果、6 つの画面が横一列に並び、**どれが守りでどれが攻めか、毎朝どこを見ればよいか** が画面から分からない。コンテンツは左寄せで、幅の広い画面では右側が空く。銘柄詳細は 7 つの節が縦に長く並ぶ。

本書では、機能を使う場面（毎朝 / 週末 / 月次）と役割（守り / 攻め / 振り返り）に沿って画面を組み直す。**機能は増やさない**。

## 2. スコープ / 非スコープ

### スコープ

- サイドバーのナビゲーション（4 項目 + 1 行の説明、件数バッジ、データの鮮度）
- コンテンツの中央寄せと幅の統一
- アクション画面（`/`）: 上部に状態の帯（鮮度・未判定・未対応数）、未対応タブが既定。毎朝の確認がここで終わる
- アクションを銘柄ごとのカードにまとめ、まとめて対応できるようにする
- 保有とウォッチを「銘柄」画面に統合（タブ）
- 銘柄詳細の再構成: ヘッダ帯 + タブ
- 表の共通改善: ヘッダの固定、空状態の統一、モバイル幅での折り返し
- DESIGN.md の Layout / Components の更新

### 非スコープ

- 新しいデータや機能（O2〜O6）。対応時のメモ入力も O2 に含める（本書では扱わない）
- ダークモード、アイコンフォント（絵文字も使わない。DESIGN.md の方針）
- 認証、複数ユーザー

## 3. 設計

### 3.1 ナビゲーション（サイドバー）

幅 220px、左固定、画面の高さいっぱい。1,024px 未満では上部の横並びに畳む。項目は 4 つ。グループ分けはせず、各項目の下に 1 行でつながりを書く。並びはよく使う順。

```
trading-tools
  株価: 2026-09-18（今日）      ← 鮮度。古ければ黄色

アクション            7        ← / 。毎朝の入口。検知と助言を確認して処理する
銘柄                            ← /instruments 。監視している銘柄（保有 / ウォッチ）
スクリーナー                    ← /screener 。候補を探してウォッチへ
履歴                            ← /history 。判断の記録（全銘柄）

────
最終収集 09-18 18:31 ✓          ← launchd の最終実行とその結果（data/logs から）
```

- 「守り / 攻め」「今日」「振り返る」のようなグループ名は使わない。壁打ちで、設計上の分類は利用者の動線と一致しない・「今日」と「アクション」は中身がほぼ同じ、と分かった
- 件数バッジは未対応のアクション数
- 鮮度は 0001 R2 の要件。今は「アクション」画面だけのバナーだが、どの画面でも見えるようにサイドバーへ移す
- 画面内の相互リンクでつながりを示す: スクリーナーで追加したら「銘柄（ウォッチ）を見る」、銘柄一覧に「スクリーナーで探す」、履歴の行から銘柄詳細のタイムラインへ

### 3.2 レイアウト

- コンテンツは **中央寄せ、最大幅 1,200px**、左右の余白 32px（サイドバーを除いた領域の中で中央）
- ページの先頭は共通の **ヘッダ帯**: タイトル（`headline-md`）、1 行の要約（`summary`）、右端に画面固有の操作（あれば）
- 節の見出し（`title-sm`）の上 32px、下 12px。今より広く取り、節の区切りを目で追えるようにする

### 3.3 アクション画面（`/`）

毎朝の確認をここで終える。「今日」画面を別に作らない（中身がアクション一覧と同じになるため）。

1. **状態の帯**: 株価の鮮度、最終収集の結果、未判定のニュース・開示の件数（「朝の確認をして」で減る）、未対応のアクション数（保有 / ウォッチ）
2. **状態タブ**: 未対応（既定）/ 対応した / 見送り
3. **銘柄ごとのカード**: 銘柄名・保有 / ウォッチ・スコア・その銘柄のアクション（重大度または「買い検討」バッジ + タイトル、本文は折りたたみ）・助言（stance バッジ + タイトル、本文と参照は折りたたみ）。カードの操作で **その銘柄の未対応をまとめて**「対応した / 見送り」にできる（同じ銘柄の複数アクションを個別に処理する手間をなくす）。個別に処理したい場合はアクションごとの操作も残す
4. 未対応タブの末尾に **スコアの大きな変動**（前回から ±10 以上。あれば）

対応時のメモ入力は O2（種別と一緒に）。

### 3.4 銘柄画面（`/instruments`）

保有とウォッチを 1 画面に統合し、タブで切り替える。両方とも「監視している銘柄の一覧」で、違いは出どころだけ。

| タブ | 列 |
| --- | --- |
| 保有（既定） | 今の保有一覧と同じ（数量、取得単価、株価、前日比、取得単価比、評価額、損益、スコア） |
| ウォッチ | 今のウォッチ一覧と同じ（追加日、メモ、株価、60 日高値比、200 日線比、スコア、未対応、外す） |

ヘッダ帯に「スクリーナーで探す」へのリンク。`/holdings` と `/watch` は廃止（`/instruments?tab=watch`）。

### 3.5 銘柄詳細（`/instruments/$id`）

- **ヘッダ帯**: 銘柄名・コード、保有 / ウォッチのバッジ、株価と前日比、スコア（内訳は小さく）、株価 1 年の折れ線。ここまでで「今どうか」が分かる
- 下は **タブ**: 概要（未対応アクションと助言、口座別の保有）/ タイムライン / ニュース・開示（判定つき）/ 財務・指標（年次の表と最新の指標。今は画面に無い）/ 株価（表）
- タブは URL の検索パラメータ（`?tab=timeline`）で切り替え、リンクで共有できる

### 3.6 表の共通改善

- ヘッダ行を固定（`position: sticky`）。長い表で列が分からなくならないように
- 1,024px 未満: 表を横スクロールにする（列を隠さない）
- 空状態は `.empty` に統一済み。文面は「次にやるコマンド」を必ず入れる（既存）
- 数値列は等幅数字で右揃え（既存）

### 3.7 パッケージ構成

| パス | 内容 |
| --- | --- |
| `apps/dashboard/src/app/layout.tsx` | サイドバー（`widgets/sidebar` を置く） |
| `widgets/sidebar` | グループ、件数、鮮度。データはルートのローダー（`routes/__root.tsx` の `loader`）で取り、`Outlet` の外に渡す |
| `pages/actions` | `/`。状態の帯 + タブ + カード |
| `pages/instruments` | `/instruments`。保有 / ウォッチのタブ（`pages/holdings` と `pages/watch` を統合） |
| `widgets/action-card` | 銘柄ごとのカード（`features/resolve-action` に複数 id の一括処理を追加） |
| `pages/instrument` | ヘッダ帯とタブ。`widgets/financials-table` を新設 |
| `app/styles.css`、`DESIGN.md` | Layout / sidebar / card / tabs / sticky header |

`docs/screens.md` は `pnpm screens` で再生成する（`/holdings` `/watch` の廃止と `/instruments` の追加が反映される）。

## 4. 検討した選択肢と決定

| 論点 | 決定 | 却下した選択肢と理由 |
| --- | --- | --- |
| ナビの置き場 | 左サイドバー | 上部のまま: 説明文や件数・鮮度を置く幅が無い。ハンバーガー: 毎朝見る画面で 1 クリック増える |
| ナビの構成 | 4 項目 + 1 行の説明、グループ無し | 守り / 攻め / 振り返り のグループ: 設計上の分類で動線と一致しない。「今日」画面: アクション一覧と中身が同じ。「振り返る」: 動詞のグループ名が不自然（壁打ち） |
| 保有とウォッチ | 1 画面にタブで統合 | 別画面のまま: どちらも「監視している銘柄」の一覧で、分ける理由が出どころだけ |
| アクションの単位 | 銘柄ごとのカード | 1 行 = 1 アクションの表のまま: 同じ銘柄の複数アクションを個別に処理する手間。助言が「同時に対応する」と書くのは UI の不備の裏返し |
| 銘柄詳細 | ヘッダ帯 + タブ | 縦に全部並べる（今）: 7 節で長く、ニュースを見るのに毎回スクロール。ページ分割: URL が増える |

## 5. リスク・未決事項

| # | 内容 | 対応 |
| --- | --- | --- |
| R1 | 画面の組み替えで既存の動作（状態変更、上書き、ウォッチ追加）を壊す | 移行前後で同じ操作をブラウザで確認（0006 と同じ手順）。機能追加はメモ入力だけ |
| R2 | サイドバーの鮮度・件数を全画面で取ると、毎回のローダーが重くなる | ルートのローダーで 1 回だけ取り、件数は軽いクエリ（count）にする |
| U1 | 「今日」画面のスコア変動の閾値（±10） | 仮。運用で調整 |

## 決定事項（壁打ちの結果）

| 論点 | 決定 |
| --- | --- |
| ナビ | サイドバー、4 項目（アクション / 銘柄 / スクリーナー / 履歴）+ 1 行の説明。グループ名は使わない |
| 今日画面 | 作らない。アクション画面（`/`）に状態の帯を足す |
| 保有 / ウォッチ | 「銘柄」画面に統合（タブ） |
| アクション | 銘柄ごとのカードにまとめ、まとめて対応できる |
| 銘柄詳細 | ヘッダ帯 + タブ |
| 対応時のメモ入力 | 本書のスコープ外（O2） |

## 実装時の補足（2026-09-20）

- ルート `/instruments` は TanStack Router のファイル名 `instruments.index.tsx` で作る（`instruments.$id.tsx` と共存）。`/holdings` `/watch` は削除
- サイドバーの状態はルートルートの `loader` で取り、`AppLayout` に渡す。銘柄ごとの `<Link>` は `activeOptions={{ includeSearch: false }}` で検索パラメータに関係なくアクティブにする
- ブラウザ幅 1,024px 未満ではサイドバーを上部に畳み、説明文と最終収集を隠す。状態の帯は 2 列に
- 銘柄詳細の株価の折れ線はヘッダの直下、スコアの折れ線はタイムラインのタブに置いた
- CSS はセレクタの詳細度が下がらない順に並べる（Biome の `noDescendingSpecificity`）
- 検証中に私（エージェント）のブラウザ操作でウォッチが 1 件追加され、アクションが 1 件見送りになった。どちらも戻した。ブラウザでの検証はデータを変える操作を含むため、検証後に状態を確認して戻す
