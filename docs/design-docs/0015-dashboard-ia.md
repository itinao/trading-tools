## 1. 背景と目的

M1〜M5 で画面を足すたびに上部ナビにリンクを並べてきた結果、6 つの画面が横一列に並び、**どれが守りでどれが攻めか、毎朝どこを見ればよいか** が画面から分からない。コンテンツは左寄せで、幅の広い画面では右側が空く。銘柄詳細は 7 つの節が縦に長く並ぶ。

本書では、機能を使う場面（毎朝 / 週末 / 月次）と役割（守り / 攻め / 振り返り）に沿って画面を組み直す。**機能は増やさない**。

## 2. スコープ / 非スコープ

### スコープ

- サイドバーのナビゲーション（グループ分け、件数バッジ、データの鮮度）
- コンテンツの中央寄せと幅の統一
- 「今日」画面（`/`）: 毎朝の確認が 1 画面で終わる構成
- アクション一覧の改善: 銘柄ごとにまとめる、対応時にメモを入れる、助言を既定で開く
- 銘柄詳細の再構成: ヘッダ帯 + タブ
- 表の共通改善: ヘッダの固定、空状態の統一、モバイル幅での折り返し
- DESIGN.md の Layout / Components の更新

### 非スコープ

- 新しいデータや機能（O2〜O6）。ただし O2 の「メモの入力」は本書で UI だけ先に入れる（種別は O2）
- ダークモード、アイコンフォント（絵文字も使わない。DESIGN.md の方針）
- 認証、複数ユーザー

## 3. 設計

### 3.1 ナビゲーション（サイドバー）

幅 220px、左固定、画面の高さいっぱい。1,024px 未満では上部の横並びに畳む。

```
trading-tools
  株価: 2026-09-18（今日）   ← 鮮度。古ければ黄色

今日                          ← /（毎朝ここだけ見れば終わる）

守り
  アクション        7        ← 未対応の件数
  保有

攻め
  ウォッチ          2
  スクリーナー

振り返り
  履歴

────
最終収集 09-18 18:31 ✓        ← launchd の最終実行とその結果（data/logs から）
```

- グループ名は 0001 の言葉（守り / 攻め / 振り返り）をそのまま使う。利用者の困りごとと対応する
- 件数バッジは未対応のアクション数（守りは保有銘柄分、攻めはウォッチ銘柄分）
- 鮮度は 0001 R2 の要件。今は「アクション」画面だけのバナーだが、どの画面でも見えるようにサイドバーへ移す

### 3.2 レイアウト

- コンテンツは **中央寄せ、最大幅 1,200px**、左右の余白 32px（サイドバーを除いた領域の中で中央）
- ページの先頭は共通の **ヘッダ帯**: タイトル（`headline-md`）、1 行の要約（`summary`）、右端に画面固有の操作（あれば）
- 節の見出し（`title-sm`）の上 32px、下 12px。今より広く取り、節の区切りを目で追えるようにする

### 3.3 「今日」画面（`/`）

毎朝の確認を 1 画面で終える。上から:

1. **状態**: 株価の鮮度、最終収集の結果、未判定のニュース・開示の件数（「朝の確認をして」で減る）、未対応のアクション数（守り / 攻め）
2. **未対応のアクション（守り）**: 銘柄ごとにまとめたカード。銘柄名・スコア・その銘柄の未対応アクション（重大度バッジ + タイトル）・助言（stance バッジ + タイトル、本文は折りたたみ）。カード内の操作で全部まとめて「対応した / 見送り」にできる（同じ銘柄の複数アクションを個別に処理する手間をなくす。0012 で助言が「同時に対応済みにする」と書いていた件）
3. **未対応のアクション（攻め）**: 同じカード形式。「買い検討」バッジ
4. **今日のスコア変動**: 前回から ±10 以上動いた銘柄（あれば）

今の `/`（アクション一覧、タブで 対応した / 見送り）は `/actions` に移し、守りのグループに置く。

### 3.4 アクション一覧（`/actions`）と対応時のメモ

- 表からカードに変える（今日画面と同じ部品）。状態タブ（未対応 / 対応した / 見送り）は残す
- 「対応した」「見送り」を押すと、その場に **メモの入力欄** が開く（1 行、任意）。0014 で「メモに何をしたか書く運用」としたが、今の UI はメモを入れられない。`resolve` の `note` を UI から渡す
- 助言は既定で **stance バッジとタイトルを表示**、本文と参照は折りたたみ（今と同じ）

### 3.5 銘柄詳細（`/instruments/$id`）

- **ヘッダ帯**: 銘柄名・コード、保有 / ウォッチのバッジ、株価と前日比、スコア（内訳は小さく）、株価 1 年の折れ線。ここまでで「今どうか」が分かる
- 下は **タブ**: 概要（未対応アクションと助言、口座別の保有）/ タイムライン / ニュース・開示（判定つき）/ 財務・指標（年次の表と最新の指標。今は画面に無い）/ 株価（表）
- タブは URL の検索パラメータ（`?tab=timeline`）で切り替え、リンクで共有できる

### 3.6 表の共通改善

- ヘッダ行を固定（`position: sticky`）。長い表で列が分からなくならないように
- 1,024px 未満: 表を横スクロールにする（列を隠さない）
- 空状態は `.empty` に統一済み。文面は「次にやるコマンド」を必ず入れる（既存）
- 数値列は等幅数字で右揃え（既存）

### 3.7 パッケージ構成

| パス | 内容 |
| --- | --- |
| `apps/dashboard/src/app/layout.tsx` | サイドバー（`widgets/sidebar` を置く） |
| `widgets/sidebar` | グループ、件数、鮮度。データはルートのローダー（`routes/__root.tsx` の `loader`）で取り、`Outlet` の外に渡す |
| `pages/today` | `/` |
| `pages/actions` | `/actions` に移動 |
| `widgets/action-card` | 銘柄ごとのカード（`features/resolve-action` にメモ入力を追加） |
| `pages/instrument` | ヘッダ帯とタブ。`widgets/financials-table` を新設 |
| `app/styles.css`、`DESIGN.md` | Layout / sidebar / card / tabs / sticky header |

`docs/screens.md` は `pnpm screens` で再生成する（`/` と `/actions` の追加・移動が反映される）。

## 4. 検討した選択肢と決定

| 論点 | 決定 | 却下した選択肢と理由 |
| --- | --- | --- |
| ナビの置き場 | 左サイドバー | 上部のまま: 6 画面をグループ分けして並べる幅が無い。ハンバーガー: 毎朝見る画面で 1 クリック増える |
| グループの軸 | 守り / 攻め / 振り返り | 画面の種類（一覧 / 詳細）: 利用者の目的と対応しない |
| アクションの単位 | 銘柄ごとのカード | 1 行 = 1 アクションの表のまま: 同じ銘柄の複数アクションを個別に処理する手間。助言が「同時に対応する」と書くのは UI の不備の裏返し |
| 銘柄詳細 | ヘッダ帯 + タブ | 縦に全部並べる（今）: 7 節で長く、ニュースを見るのに毎回スクロール。ページ分割: URL が増える |
| 「今日」画面 | 新設して `/` に | アクション一覧に状態を足す: 一覧は状態タブを持つ「記録」の画面で、朝の「確認」とは役割が違う |

## 5. リスク・未決事項

| # | 内容 | 対応 |
| --- | --- | --- |
| R1 | 画面の組み替えで既存の動作（状態変更、上書き、ウォッチ追加）を壊す | 移行前後で同じ操作をブラウザで確認（0006 と同じ手順）。機能追加はメモ入力だけ |
| R2 | サイドバーの鮮度・件数を全画面で取ると、毎回のローダーが重くなる | ルートのローダーで 1 回だけ取り、件数は軽いクエリ（count）にする |
| U1 | 「今日」画面のスコア変動の閾値（±10） | 仮。運用で調整 |

## 要確認

1. サイドバーのグループ（今日 / 守り / 攻め / 振り返り）でよいか
2. アクションを **銘柄ごとのカード** にまとめ、まとめて対応できるようにしてよいか（表のままがよければそれも可）
3. 「今日」画面を新設して `/` にし、今のアクション一覧を `/actions` に移してよいか
4. 銘柄詳細をヘッダ帯 + タブにしてよいか
5. 他に、今の画面で使いにくいと感じている点があれば
