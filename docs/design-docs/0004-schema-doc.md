## 1. 背景と目的

Design Doc は変更ごとに書くため、ER 図が複数の文書に分散する。「今の全テーブル」を **固定の場所で常に最新の状態で**見たい。手で維持する図は古くなるので、スキーマ定義から自動生成する。

## 2. スコープ / 非スコープ

- スコープ: `packages/db/src/schema/` から Mermaid の ER 図を生成し `docs/schema.md` に書く。古くなっていたらテストで検出する
- 非スコープ: 図の見た目の調整、テーブルの説明文の自動抽出（コメントは各 Design Doc を参照）

## 3. 設計

- `pnpm db:erd` で `docs/schema.md` を生成する。Drizzle の `getTableConfig` から列・型・主キー・外部キー・一意制約を読む
- `packages/db/test/erd.test.ts` が「生成結果 == コミット済みの `docs/schema.md`」を検証する。スキーマを変えて `db:erd` を忘れると `pnpm test` が落ちる
- `AGENTS.md` の「スキーマの変え方」に `pnpm db:erd` を加える
- 生成物には「手で編集しない」旨と、各テーブルを定義した Design Doc へのリンクを含める

## 4. 検討した選択肢と決定

| 論点 | 決定 | 却下した選択肢と理由 |
| --- | --- | --- |
| 生成元 | Drizzle スキーマ（TypeScript） | SQLite の実 DB から: マイグレーションを当てないと見られない。マイグレーション SQL から: 差分の積み重ねで現在形を出すのが面倒 |
| 鮮度の担保 | テストで検証 | pre-commit hook: エージェント環境で hook が動く保証がない。テストは必ず走る |
